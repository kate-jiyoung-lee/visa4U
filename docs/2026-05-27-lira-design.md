> **작성일**: 2026-05-27

> **프로젝트**: 의회 AI 바이브 코딩 워크숍 팀 출품작 (법제과)

## 1. 프로젝트 개요

### 1.1 프로젝트명

- **LIRA** (Legislative Intelligent Review Assistant)
- 한글명: **의안 자동 검토 어시스턴트**
- 표어: *"입법, 다시 한 번 점검하는 AI 동료"*

### 1.2 한 줄 정의

> 의원 발의안·조례안 텍스트를 입력하면, **법제처 자치법규 입안 길라잡이 등 공식 기준**을 근거로 **인용 무결성·법체계 적법성·자치법규 정합성·입법기술·양성평등·차별·영향** 5가지를 자동 점검하고, **출처가 명시된 검토의견서 초안**을 생성하는 **단일 HTML 도구**.

### 1.3 목적

1. **법제과 직원의 실수 방지** — 검토 보고서 작성 시 인용·위법 누락을 1차 자동 점검
2. **양성평등·차별 표현 점검 자동화** — 현행 검토의견서가 약한 영역 보강
3. **검토 시간 단축이 아닌 검토 품질 향상** — 빠르게 끝내는 게 아니라, 빠진 부분 잡아내는 도구
4. **확산성 확보** — 타 광역의회·기초의회 법제과도 즉시 사용 가능한 표준 도구
5. **AI 시대 의회 모범 사례 제시** — 비용 0원·다중 AI 지원 구조로 진입장벽 ↓

### 1.4 핵심 가치 명제

> **"속도가 아니라 정확성을 높이는 AI."**

### 1.5 출품작 어필 포인트

| 어필 포인트 | 한 줄 |
|---|---|
| 🛠 실용성 | "법제과가 매일 쓰는 도구" |
| 📚 신뢰성 | "법제처 자치법규 입안 길라잡이 페이지까지 인용하는 AI" |
| 💸 비용 0원 가능 | "Gemini 무료 티어로 누구나 즉시 사용" |

| 🌐 단일 HTML | "설치 불필요, 사내 보안 충돌 없음" |

## 2. 핵심 사용자·시나리오

### 2.1 주 사용자

| 우선순위 | 사용자 | 활용 시점 |
|---|---|---|
| 🥇 1순위 | **법제과 법률자문관·입법조사관** | 의원 발의안 수령 직후 1차 점검 |
| 🥈 2순위 | **의원실 보좌관·정책담당관** | 의원 발의 전 자체 점검 |
| 🥉 3순위 | **타 광역의회·기초의회 법제과** | 표준 도구로 확산 |

### 2.2 대표 사용 시나리오

#### 시나리오 1 — 법제과의 1차 점검

```
1. 의원실에서 발의안 도착
2. 법률자문관이 LIRA 열기 → 발의안 텍스트 붙여넣기
3. "검토 시작" 클릭
4. 약 30초 후 5개 영역 검토 결과 출력 (출처 명시)
5. 법률자문관이 결과를 1차 자료로 활용해 최종 검토의견서 작성
6. 시간 절약 + 누락 방지
```

#### 시나리오 2 — 의원실 자체 점검

```
1. 의원실 보좌관이 발의 전 LIRA로 셀프 체크
2. 인용 오류·위법 소지 사전 발견
3. 수정 후 발의 → 법제과 검토 통과율 ↑
4. 입법 효율성 ↑
```

## 3. 기능 명세 — 5가지 검토 영역

법제처 자치법규 입안 길라잡이의 공식 체크리스트 12개 항목을 5개 검토 영역으로 통합.

### ① 인용 무결성 검증

| 항목 | 내용 |
|---|---|
| 점검 대상 | 발의안에 인용된 법령·조례 조항 |
| 데이터 소스 | 국가법령정보센터 OpenAPI |
| 출력 | 인용 법령별 유효성·정확성 검증 결과 |
| 예시 | "안 제3조에서 「○○법」 제5조 인용 → 2024년 폐지" |

### ② 법체계 적법성 검토

| 점검 항목 | 근거 |
|---|---|
| 사무 구분 (국가사무 vs 자치사무) | 지방자치법 §13·§15 |
| 상위법 위반 여부 | 법령 우위의 원칙 |
| 권리의무·위임범위 | 법률유보의 원칙 |
| 견제와 균형 (집행기관 권한 침해) | 지방자치법 §117·§118 |

### ③ 자치법규 정합성 검토

| 점검 항목 | 내용 |
|---|---|
| 다른 조례와의 충돌 | 동일 의회 내 다른 조례 검색·비교 |
| 정비 필요성 | 다른 조례 폐지·개정 필요 여부 |
| 입법방식 (제정 vs 개정) | 기존 조례 활용 가능성 |

### ④ 입법기술 점검

| 점검 항목 | 근거 |
|---|---|
| 시행일 적정성 | 공포일 시행 vs 시행 유예 |
| 경과조치 | 기존 제도 변경 시 |
| 적용례 | 신설 제도 |
| 부칙 작성원칙 | 법제처 입안 길라잡이 |

### ⑤ 양성평등·차별·영향 통합 점검

| 점검 항목 | 근거 |
|---|---|
| 차별적 용어 | 법령정비기준 §5 (성차별·장애인 비하 등) |
| 권위적 용어 | 법령정비기준 §5 |
| 일본식·어려운 한자어 | 법령정비기준 §3 |
| 양성평등 영향평가 | 양성평등기본법 §15 |
| 위원회 성비 점검 | 양성평등기본법 §21 |
| 약자·안전·기득권 영향 | 법제처 입안 길라잡이 |

## 4. 출력 양식 — 검토의견서 5단 구조

### 4.1 헤더

```
자치법규안 검토의견서 — AI 사전 점검
자치법규 제명: 「○○ 조례안」
관계 법령: 「○○법」, 「○○법」 등
검토기준: 법제처 자치법규 입안 길라잡이(2022) 등
```

### 4.2 각 항목별 5단 구조

```
○ 카테고리명 — 세부 항목명

▸ 발견 사항
[발견된 사실, 안 제X조에서 ~을 규정]

📜 관련 법령
• 「○○법」 제X조 → 적합 ✓ / 부적합 ⚠ / 검토 필요 ❓

📖 참고자료
• 법제처, 『자치법규 입안 길라잡이』, 2022, pp.X-Y

💭 판단 이유
[법령·자료를 적용한 추론]

💡 검토 의견
[수정 / 제안 / 권고]
```

### 4.3 푸터

```
종합: 수정 N건 / 제안 M건 / 검토필요 K건
※수정 사항은 붉은색, 제안 사항은 푸른색
※본 점검은 AI 1차 보조이며, 최종 판단은 입법조사관 검토 필요

검토일시: 2026-05-27 14:30
검토도구: LIRA v0.1 (Claude API 기반)
```

## 5. 시스템 아키텍처

### 5.1 전체 구조

```
[사용자 브라우저]
   │
   ├── 단일 HTML (index.html)
   │     ├── UI (입력·결과 표시)
   │     ├── 인용 추출 모듈 (정규식)
   │     ├── 카테고리 라우터 (5개 기능 → 관련 chunk 매핑)
   │     └── AI 호출 모듈 (Multi-AI: Claude/Gemini)
   │
   ├── 임베딩 자료 (JSON, 같은 폴더)
   │     ├── 자치법규입안길라잡이_chunks.json
   │     ├── 법령정비기준_chunks.json
   │     └── 법령입안심사기준_chunks.json
   │
   └── 외부 API
         ├── 국가법령정보센터 OpenAPI (법령 유효성·조회)
         └── Claude API or Gemini API (AI 분석)
```

### 5.2 데이터 흐름 (한 건 검토)

```
1. 사용자가 발의안 텍스트 입력
2. 인용 추출: 정규식으로 「○○법」 제X조 등 자동 추출
3. 국가법령정보센터 API 호출 → 인용 법령 유효성 확인
4. 5개 카테고리별로:
   a. 관련 chunk 선택 (키워드·카테고리 매칭)
   b. 시스템 프롬프트 + 발췌본 + 발의안 → AI 호출
   c. 응답 파싱 → 5단 구조로 렌더링
5. 종합 결과 + 출처 명시된 검토의견서 출력
```

## 6. AI 추상화 인터페이스 (Multi-AI)

### 6.1 지원 AI

| AI | 비용 | 용도 |
|---|---|---|
| Claude Sonnet 4.6 | 사용량 만큼 (월 ~1만원) | 시연·고정밀 검토 |
| Gemini 1.5 Flash | 무료 (일 1,500요청) | 일반 보급 |
| (향후) 네이버 CLOVA | 일부 무료 | 공공기관용 |

### 6.2 인터페이스

```javascript
async function callAI(provider, apiKey, systemPrompt, userPrompt) {
  switch(provider) {
    case 'claude':  return callClaude(apiKey, systemPrompt, userPrompt);
    case 'gemini':  return callGemini(apiKey, systemPrompt, userPrompt);
    case 'naver':   return callNaver(apiKey, systemPrompt, userPrompt);
  }
}
```

→ UI에 드롭다운으로 AI 선택, API 키 입력 한 번.

## 7. 에러 처리·신뢰성

| 상황 | 처리 |
|---|---|
| API 키 미입력 | 알림창 "API 키를 먼저 입력하세요" |
| 발의안 텍스트 미입력 | 알림창 "점검할 텍스트를 입력하세요" |
| API 호출 실패 | 결과 영역에 오류 + 콘솔 로그 |
| 인용 법령 매칭 실패 | "검토 필요"로 표시 (환각 방지) |
| AI 출처 누락 | 자동 검증 → 출처 없으면 "검토 필요"로 다운그레이드 |

### 신뢰성 정책

- 모든 AI 응답은 **출처 명시 의무**
- 출처 없으면 자동으로 "검토 필요" 등급
- 시스템 프롬프트에 "추측·환각 금지" 명시
- 화면 하단에 안내문 상시 표시:
  > "본 분석은 AI에 의한 1차 보조이며, 최종 판단은 입법조사관·법제과 변호사 자문이 필요합니다."

## 9. 시연 시나리오·발표 포인트

### 9.1 1분짜리 데모 시나리오

> 1. "실제 의원 발의안 「○○ 조례 일부개정조례안」입니다. LIRA에 넣어보겠습니다."
> 2. **드롭다운에서 Claude 선택** → 텍스트 붙여넣기 → 검토 시작
> 3. 30초 후 결과 표시
> 4. "보세요. 인용 오류 2건, 양성평등 영향평가 누락 1건, 견제와 균형 위배 의심 1건이 발견됐습니다. 각 항목마다 **법제처 자치법규 입안 길라잡이 페이지 번호까지 인용** 되어 있습니다."
> 5. "그리고 비용이 부담되시면 **Gemini 무료로 갈아끼울 수 있습니다.**"
> 6. 드롭다운에서 Gemini로 전환 → 같은 검토 다시 → 동등 수준 결과
> 7. "비용 0원, 누구나 즉시 사용 가능합니다."

### 9.2 발표 핵심 메시지 3가지

1. **"법제처 공식 기준을 페이지까지 인용하는 AI"** — 신뢰성
2. **"AI 모듈 교체 가능 구조"** — 미래 확장성
3. **"양성평등·차별 표현까지 통합 검토"** — 현행 보고서의 약점 보강

### 9.3 차기 의장 어젠다와의 연결

- **지방의회 위상 강화** (남종섭) → "타 광역의회 표준 도구"
- **정책보좌관 지원** (남종섭) → 의원실 보좌관 보급 가능
- **사회적 약자 보호** (남종섭) → 양성평등·약자 영향 통합 점검
- **콘텐츠·홍보** (김진경) → 시연 영상·언론 보도자료 활용 가능

## 부록 A. 결정 근거 정리

- **단일 HTML 채택**: CASA 가이드 패턴 / 설치·서버 불필요 / 사내 보안 충돌 없음
- **방식 A (RAG) 처음부터 채택**: 출처 신뢰성 1주차부터 확보
